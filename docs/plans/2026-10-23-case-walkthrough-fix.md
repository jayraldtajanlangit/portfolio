# Case-study walkthrough playback fix

Reported behavior: clicking a project opens a case study without an obvious playable walkthrough.

Root causes found in the renderer/controller: case-study video HTML omits native controls and offers only the original WebM source, while the homepage has the guided H.264 MP4 versions. The legacy media controller disables controls until a JavaScript-only Open media action is used, so no-JavaScript/local-file paths have no playback affordance. Autoplay-policy rejection also incorrectly marks the video failed and hides it in favor of a screenshot.

Fix all five case-study pages: add a clear Project walkthrough heading, put native controls in the generated HTML, load the polished MP4 first with WebM fallback, and provide an always-visible direct MP4 link. Treat inline players as open in the controller, retain their controls on Escape, and keep the player available after autoplay-policy rejection. Genuine decoding/network errors still show the existing screenshot fallback. Keep portrait recordings at a comfortable viewport height with native controls fitted to the phone video rather than requiring a huge full-page expansion.

Regression tests cover all five generated players, source paths, controls without JavaScript, direct video links, inline controller initialization/Escape, and autoplay denial. Browser validation must click homepage case-study links, decode/play every MP4, check phone and desktop layouts, reduced-motion manual play, disabled JavaScript and local-file playback.

Verification completed: 39 automated tests and 62 browser checks passed. Every homepage project link opened a case study with a playable guided MP4; all five players passed light/dark layouts at 320, 390, 1440 and 1857px, reduced-motion manual playback, disabled JavaScript and local-file playback. Simulated autoplay rejection preserved the player and a manual retry succeeded. Eight landscape/portrait screenshots were reviewed across phone/desktop and both themes. Read-only code review found no actionable regressions.

Visual review: the walkthrough heading, native controls and direct video link make playback discoverable. Portrait recordings remain centered at a manageable height, and phone layouts have no horizontal overflow. The existing case-study typography and content order are preserved. Browser evidence is stored in `.taste-skill/case-walkthrough-final/results.json` with the reviewed screenshots alongside it.

Container follow-up: the height cap shrank the landscape stage to its aspect ratio while the outer card remained 1400px wide, leaving an empty strip on the right. The renderer now exposes the orientation and aspect ratio on the outer card. Landscape cards use the same height limit and ratio to calculate their width and center within the page; the stage explicitly fills that width. The heading, video and caption therefore share a common frame. All 39 unit tests passed, and 50 focused browser layout checks passed across all five projects, both themes and widths 320, 390, 768, 1522 and 1857px. Reviewed phone and desktop screenshots confirm the empty strip is removed, controls remain visible and portrait videos stay centered. Evidence: `.taste-skill/walkthrough-container/`.
