# Portfolio walkthroughs

Source recordings are the un-suffixed `.webm` files. The five `-polished.mp4` files are separate 60fps H.264 exports. SkyFire and mAIstra retain the guided presentation cursor and show the complete application screen throughout playback, without zooming or cropping. The three portrait mobile walkthroughs stay at their original full-screen scale, with no desktop cursor, zoom or camera movement; brief expanding tap rings show interactions. Matching `-polished.webm` mobile fallbacks use the same presentation. Loading lead-ins are trimmed according to each clip's motion profile; the recaptured mAIstra and Pulso sequences start immediately and have no trim.

The desktop cursor is authored from `demo-cursor.svg`; `demo-cursor.png` is the transparent export used by FFmpeg. Camera, cursor and labeled tap cues are in `scripts/walkthrough-motion.mjs`. The mobile compositor in `scripts/walkthrough-touch.mjs` draws each fading touch ring for 0.48 seconds at its fixed screen position. These follow the visible application steps and are authored presentation cues, not recovered pointer/touch telemetry. Application screens and results are preserved.

Regenerate the polished clips with `npm run render:walkthroughs` (FFmpeg must be installed), or render a single clip with `node scripts/render-walkthroughs.mjs skyfire`. Original recordings are preserved. Effects are baked into each MP4, including native fullscreen and video downloads. Homepage previews loop muted together while visible, without playback bars or hover requirements. Click/tap a preview, or focus it and press Space/Enter, to pause/resume it. `js/walkthrough.js` also pauses offscreen/background playback and respects reduced motion. Case-study pages provide full native playback controls.

The mAIstra clip was recaptured on October 24, 2026 to include the OCR step. It shows an unprocessed handwritten submission, Extract now, the recognized text, teacher verification and two accepted demo test cases. Its full-frame camera keeps the handwritten page and OCR text visible together. The OCR output comes from a real local run of the project's OpenCV/PaddleOCR pipeline on `samples/bond/bond_writer1_1.jpg`; the recording replays that result with shortened waiting. Supabase persistence and Judge0 grading responses use the project's isolated test backend. The video does not show Flutter mobile capture or establish live-service performance.

For a fresh capture, the neighboring mAIstra checkout needs its installed Python/OCR and web dependencies, model weights, and an Angular build. Run `npm run build` inside `mAIstra/maistra_web` first; the capture serves `dist/maistra_web_temp/browser`. Then, from this portfolio, run `python scripts/prepare-maistra-ocr-demo.py` followed by `node scripts/capture-maistra-ocr-walkthrough.mjs`. These write review artifacts under `.taste-skill/maistra-ocr-recording/`; inspect the screenshots and capture manifest before replacing public media. The existing pre-OCR recordings and stills were backed up there under `previous/` during this update.

The Pulso clip was recaptured on October 24, 2026 to show sign-in, a create-account screen preview, demo login, image selection and publishing, liking/bookmarking, profile/avatar editing and sign-out. It runs the real Flutter screens/controllers with in-memory repositories and the normal browser image picker. Authentication accepts only a fictional local demo account and clears its session at sign-out; the registration screen is previewed without submitting an account. The image is this portfolio's social card and the avatar is a fictional initials graphic. Authentication, follower counts, storage and social state are demo fixtures; no live account registration, email confirmation, authentication, uploads or realtime delivery are demonstrated.

For Pulso, run `python scripts/prepare-pulso-demo.py` with the neighboring `Pulso` checkout, Flutter SDK, Pillow and cached Pulso package dependencies available. It copies only app source/platform files and package manifests into `.taste-skill/pulso-image-recording/app`, adds the capture entry point and bundles the SDK's default Roboto font locally. In that isolated app directory run `flutter pub get --offline` (a fresh package cache needs a one-time `flutter pub get` with network access), then `flutter build web --release --no-pub --no-web-resources-cdn --no-wasm-dry-run --target lib/portfolio_demo.dart`. Back in the portfolio, run `node scripts/capture-pulso-images.mjs`; it uses the installed Playwright package in the neighboring mAIstra web checkout and installed Chrome. Inspect its screenshots and `capture.json` before replacing public media. The earlier Pulso media is preserved under `.taste-skill/pulso-image-recording/previous/`.
